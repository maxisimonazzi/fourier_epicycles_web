Una figura cualquiera, recorrida como un punto que se mueve, se puede escribir como una suma de vectores que giran. Cada vector es un círculo. Esta página hace ese cálculo con la figura que elijas en el Estudio y lo convierte en video.

Esto es el resumen. El tutorial completo, con figuras interactivas y las cuentas hechas para el círculo, la elipse, el cuadrado, los polígonos y un SVG, está en Del círculo al SVG.

1La figura como un punto que se mueve

Recorremos el contorno a velocidad constante mientras un tiempo \(t\) va de 0 a 1. En cada instante el lápiz está en un punto del plano. Si escribimos ese punto como número complejo, toda la figura queda guardada en una sola función periódica:

\[ z(t) = x(t) + i\,y(t), \qquad z(t+1) = z(t). \]

2Un círculo es un número complejo

La serie de Fourier escribe ese movimiento como una suma de términos que giran a velocidades enteras:

\[ z(t) = \sum_{n=-\infty}^{\infty} c_n\, e^{2\pi i n t} \]
  • \(|c_n|\) es el largo del vector, es decir, el radio de su círculo.
  • \(\arg c_n\) es el ángulo desde el que arranca.
  • \(n\) es cuántas vueltas da mientras el lápiz recorre la figura una vez. Si \(n\) es negativo, gira al revés.
  • \(c_0\) no gira: es el centro de masa del recorrido, donde se apoya la cadena.

Sumar los vectores es ponerlos uno a continuación del otro. La punta del último es el lápiz.

3De dónde salen los coeficientes

\[ c_n = \int_0^1 z(t)\, e^{-2\pi i n t}\, dt \]

Multiplicar por \(e^{-2\pi i n t}\) hace girar todo en sentido contrario a velocidad \(n\). El único término que queda quieto es el que giraba justo a esa velocidad; los demás dan vueltas completas y su promedio es cero. Promediar en \(t\) deja solo \(c_n\).

Con \(M\) puntos equiespaciados \(z_k = z(k/M)\), la integral se convierte en una suma. Esa suma es la transformada discreta de Fourier (DFT):

\[ c_n \approx \frac{1}{M}\sum_{k=0}^{M-1} z_k\, e^{-2\pi i\, n k / M} \]

La FFT calcula los \(M\) coeficientes de una vez, con del orden de \(M \log_2 M\) operaciones. Acá \(M = 2048\) y el cálculo tarda unos milisegundos.

4Del SVG a la curva

  1. Muestrear por longitud de arco. Un SVG está hecho de segmentos, curvas de Bézier y arcos. Se lee cada trazo, se lo aproxima con tramos rectos muy cortos y se toman puntos equiespaciados sobre ese recorrido. Así el lápiz va a velocidad constante. Si fuera más rápido en unos tramos que en otros, los coeficientes cambiarían aunque la figura fuera la misma.
  2. Unir las partes. Una figura con agujeros o con piezas sueltas no es una sola curva cerrada. La herramienta busca las conexiones más cortas entre todas las partes (un árbol de expansión mínima). El lápiz cruza cada puente, recorre la parte y vuelve por el mismo puente, así que la curva nunca salta. Con «puentes ocultos» ese camino de ida y vuelta existe pero no se dibuja.
  3. Calcular y ordenar. Se aplica la FFT a los 2048 puntos. Si vas a usar \(N\) círculos, los \(N\) de mayor radio dan el menor error posible para esa cantidad.

5Por qué más círculos dan más detalle

Por la igualdad de Parseval, la «energía» de la figura se reparte entre los coeficientes, y el error cuadrático medio de quedarse solo con un conjunto \(K_N\) de términos es exactamente lo que se descarta:

\[ \int_0^1 |z(t)|^2\,dt = \sum_{n} |c_n|^2, \qquad \text{error}^2 = \sum_{n \notin K_N} |c_n|^2 . \]

Por eso conviene usar los más grandes. Qué tan rápido se achican los coeficientes depende de la forma:

  • En una curva suave decaen muy rápido y pocos círculos alcanzan.
  • Con esquinas decaen como \(1/n^2\): las puntas quedan redondeadas hasta que \(N\) es grande.
  • Con saltos, es decir cuando el lápiz pasa de un punto a otro sin recorrer el camino, decaen como \(1/n\) y aparece el fenómeno de Gibbs: cerca del salto la suma se pasa alrededor de un 9 % y oscila, por más círculos que agregues. Por eso la herramienta nunca hace saltar al lápiz: siempre lo lleva por un camino, visible u oculto.

6La versión con dos series (como el reel del colibrí)

En lugar de una cadena compleja se usan dos series reales, una por coordenada:

\[ x(t) = a_0 + \sum_{k=1}^{N} \big(a_k \cos 2\pi k t + b_k \sin 2\pi k t\big) \] \[ y(t) = c_0 + \sum_{k=1}^{N} \big(c_k \cos 2\pi k t + d_k \sin 2\pi k t\big) \]

Cada serie se dibuja como su propia cadena. La de arriba controla \(x\): la posición horizontal de su punta es \(x(t)\). La de la izquierda controla \(y\). El lápiz está donde se cruzan las dos guías punteadas. Los coeficientes salen de la misma FFT: si \(X_k\) es la DFT de las coordenadas \(x\), entonces \(a_k = 2\,\mathrm{Re}\,X_k\) y \(b_k = -2\,\mathrm{Im}\,X_k\).

7El cálculo, en pocas líneas

En JavaScript, con los puntos ya muestreados en dos arreglos x e y de largo \(M\) (potencia de 2) y una función fft que transforma en el lugar:

const re = Float64Array.from(x), im = Float64Array.from(y);
fft(re, im);                                   // DFT en O(M log M)
const c0 = { re: re[0] / M, im: im[0] / M };   // centro de la cadena
const terminos = [];
for (let j = 1; j < M; j++) {
  const n = j < M / 2 ? j : j - M;             // frecuencia con signo
  terminos.push({ n, re: re[j] / M, im: im[j] / M });
}
terminos.sort((a, b) => Math.hypot(b.re, b.im) - Math.hypot(a.re, a.im));
const usados = terminos.slice(0, N);           // los N círculos más grandes

function lapiz(t) {                            // t entre 0 y 1
  let px = c0.re, py = c0.im;
  for (const { n, re, im } of usados) {
    const a = 2 * Math.PI * n * t;             // c·e^{ia} = (re + i·im)(cos a + i·sen a)
    px += re * Math.cos(a) - im * Math.sin(a);
    py += re * Math.sin(a) + im * Math.cos(a);
  }
  return [px, py];                             // cada suma parcial es el centro de un círculo
}

Lo mismo en Python con NumPy:

import numpy as np
z = x + 1j * y                                  # M muestras equiespaciadas
M = len(z)
c = np.fft.fft(z) / M                           # coeficientes c_n
n = np.fft.fftfreq(M, 1 / M).astype(int)        # frecuencias con signo
orden = np.argsort(-np.abs(c))
orden = orden[n[orden] != 0][:N]                # los N más grandes, sin c_0
t = np.linspace(0, 1, 4000, endpoint=False)
dibujo = c[0] + (c[orden, None] * np.exp(2j * np.pi * n[orden, None] * t)).sum(axis=0)

8Cómo contarlo en un reel de 30 segundos

  • 0-2 sGancho: el dibujo final, o una pregunta. «¿Cuántos círculos hacen falta para dibujar un dragón?»
  • 2-12 sN = 1, 2, 5, 10… El dibujo empieza como un círculo y de a poco se parece a algo. Que se vea el contador.
  • 12-22 sLa idea en una frase: «cada círculo gira a una velocidad entera; Fourier dice cuánto mide cada uno y desde dónde arranca».
  • 22-30 sFigura completa y pregunta para comentarios: «¿Qué dibujo hago la próxima con 500 círculos?»

En la descripción del reel conviene contar un detalle no obvio, por ejemplo que el orden y la velocidad con que el lápiz recorre la figura cambian todos los coeficientes, aunque la figura sea la misma.
